# AI 辅助开发 · Prompt 文件

本项目按 PRD §15.2 用分阶段、小任务方式驱动 AI 编程助手。每次任务用以下模板明确边界与验收，避免一次性生成整套系统。

## 通用任务 Prompt 模板

```
项目：企业级合同用印与审批平台

当前阶段：<阶段号> - <阶段名>

任务：<一句话任务>

技术约束：
- React + TypeScript + Ant Design 6，沿用现有 Ant Design Pro 工程。
- 后端 NestJS + TypeScript + Prisma。
- 不得引入新的全局状态管理工具（前端禁 Redux/Zustand）。
- 前后端单仓。

业务约束：
1. <业务规则 1>
2. <业务规则 2>

交付要求：
1. 完整代码 + 类型定义。
2. 必要的单元/e2e 测试。
3. 修改文件清单。
4. 测试执行结果。

验收：
- <验收标准 1 通过测试>
- 不得顺带重构其他模块。
```

## 本项目已落地的阶段划分（可作拆分范例）

0 需求冻结 → 1 前端模板清理 → 2 骨架路由 → 3 DB/后端框架 → 4 认证鉴权 → 5 申请+文件 → 6 快照+提交 → 7 审批状态机 → 8 台账脱敏下载 → 9 异步导出 → 10 联调测试 → 11 部署交付。

每阶段设门禁：类型检查通过 + 相关测试通过 + 关键业务场景验证 + Git 提交。

## 关键业务规则（AI 开发时须遵守）

1. 金额后端裁决，不信前端合计；DECIMAL(18,2)，两位小数。
2. 保密协议：仅公章 + 金额=0。
3. 审批链是提交时快照，禁止读时重算覆盖。
4. 驳回=终态（≥10 字原因）；转交同部门+审批资格；加签同级/上级。
5. 所有权限/数据范围后端二次校验，禁止只靠前端隐藏按钮。
6. 终态操作按钮 DOM 彻底移除 + 后端 API 拒绝。
7. 附件私有存储 + 签名 URL，禁止公开静态目录。
8. 导出流式/游标分批，禁止 select * 拼大数组。
